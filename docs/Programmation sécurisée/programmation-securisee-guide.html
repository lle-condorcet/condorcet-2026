🎯 OWASP (Open Web Application Security Project)

Définition

OWASP est une organisation à but non lucratif qui se concentre sur l'amélioration de la sécurité logicielle. Elle fournit des ressources gratuites et ouvertes pour aider les organisations à développer, acheter et maintenir des logiciels et des applications sûrs.

Objectif principal

  • Identifier et documenter les failles de sécurité les plus critiques des applications web
  • Fournir des ressources éducatives et des outils de sensibilisation
  • Promouvoir les meilleures pratiques de sécurité en matière de développement
  • Créer une communauté mondiale d'experts en sécurité

OWASP Top 10

L'une des publications les plus populaires d'OWASP, mise à jour tous les 3-4 ans. La version 2021 identifie les 10 risques de sécurité les plus critiques pour les applications web.

🔴 A01:2021 - Injection

Failles d'injection de code (SQL, LDAP, OS). Défaut de validation des données entrantes.

🔴 A02:2021 - Broken Authentication

Mécanismes d'authentification cassés permettant une usurpation d'identité.

🔴 A03:2021 - Broken Access Control

Défaut de vérification des autorisations. Accès non restreint aux ressources.

🔴 A04:2021 - XML External Entity (XXE)

Exploitation de processeurs XML vulnérables.

🔴 A05:2021 - Broken Access Control

Limitations insuffisantes des accès utilisateurs.

🔴 A06:2021 - Vulnerable & Outdated Components

Utilisation de bibliothèques et frameworks obsolètes.

🔴 A07:2021 - Identification & Authentication Failures

Gestion faible des sessions et des mots de passe.

🔴 A08:2021 - Software & Data Integrity Failures

Absence de vérification d'intégrité des données.

🔴 A09:2021 - Logging & Monitoring Failures

Absence de logs de sécurité et de surveillance.

🔴 A10:2021 - Server-Side Request Forgery (SSRF)

Exploitation de requêtes serveur non validées.

Utilisation pratique

🎯 Cas d'usage

  • Développeurs : Guide des pratiques de codage sécurisé
  • Testeurs de sécurité : Checklist de test de pénétration
  • Architectes : Design sécurisé d'applications
  • DevSecOps : Intégration de la sécurité dans CI/CD
  • Auditeurs : Évaluation des risques de sécurité

Exemple concret - Prévention d'injection SQL

❌ Code vulnérable (OWASP A01)

// Mauvais : Construction de requête avec concaténation
String query = "SELECT * FROM users WHERE username = '" + username + "'";
ResultSet rs = statement.executeQuery(query);

✅ Code sécurisé

// Bon : Utilisation de prepared statements
String query = "SELECT * FROM users WHERE username = ?";
PreparedStatement stmt = connection.prepareStatement(query);
stmt.setString(1, username);
ResultSet rs = stmt.executeQuery();

  • WebGoat : Application d'apprentissage pour pratiquer les attaques

🐛 CWE (Common Weakness Enumeration)

Définition

CWE est une liste complète et catégorisée des faiblesses de logiciel et de matériel communes qui peuvent mener à des vulnérabilités de sécurité. C'est une référence complète pour l'identification et la classification des faiblesses dans le code.

Objectif principal

  • Créer une taxonomie standardisée des faiblesses logicielles
  • Faciliter la communication entre les développeurs et les chercheurs en sécurité
  • Automatiser la détection des faiblesses avec des outils
  • Mesurer la couverture des tests de sécurité

Relation OWASP vs CWE

Aspect OWASP Top 10 CWE
Portée Applications web uniquement Tous les types de logiciel
Nombre d'items 10 risques 900+ faiblesses
Focus Risques métier et impact Détails techniques des faiblesses
Utilisation Guide de haut niveau Détection automatisée

CWE Top 25 (Édition 2023)

Les 25 faiblesses logicielles les plus dangereuses et les plus utilisées par les attaquants :

CWE-787 : Out-of-bounds Write

Écriture au-delà des limites d'un buffer. Critique pour les dépassements de buffer.

CRITIQUE

CWE-79 : Cross-site Scripting (XSS)

Injection de code JavaScript dans les pages web. Non-échappement des données.

CRITIQUE

CWE-89 : SQL Injection

Injection de commandes SQL dans les requêtes de base de données.

CRITIQUE

CWE-200 : Exposure of Sensitive Information

Exposition accidentelle de données sensibles (clés, tokens, mots de passe).

ÉLEVÉ

CWE-416 : Use-After-Free

Utilisation de mémoire après sa libération. Peut causer des crashes ou RCE.

CRITIQUE

CWE-22 : Path Traversal

Accès à des fichiers/répertoires en dehors du répertoire autorisé.

ÉLEVÉ

Utilisation pratique

🛠️ Applications

  • SAST Tools : SonarQube, Checkmarx, Fortify utilisent CWE
  • Bug Bounty : Référence commune pour signaler les vulnérabilités
  • Code Review : Checklist standardisée de faiblesses
  • Métriques de sécurité : Mesurer le CWE density du code
  • Cartographie CVE : Chaque CVE est mappé à des CWE

Exemple concret - CWE-79 (XSS)

❌ Code vulnérable (CWE-79)

// Affichage direct du paramètre utilisateur
String comment = request.getParameter("comment");
out.println("<p>" + comment + "</p>");
// Entrée malveillante : <script>alert('XSS')</script>

✅ Code sécurisé

// Échappement HTML des données
String comment = request.getParameter("comment");
String escaped = escapeHtml(comment);
out.println("<p>" + escaped + "</p>");

private String escapeHtml(String s) {
    return s.replaceAll("&", "&")
            .replaceAll("<", "<")
            .replaceAll(">", ">")
            .replaceAll("\"", """);
}

⚠️ CVE (Common Vulnerabilities and Exposures)

Définition

CVE est un identifiant public unique pour chaque vulnérabilité de sécurité découverte. Chaque CVE a un identifiant au format CVE-ANNÉE-NUMÉRO (ex: CVE-2021-44228) et est lié à des faiblesses CWE.

Objectif principal

  • Fournir un identifiant public et standardisé pour chaque vulnérabilité
  • Faciliter le partage d'informations entre les organisations
  • Permettre le tracking et la gestion des vulnérabilités
  • Faciliter les recherches et la gestion des correctifs
  • Prioriser les efforts de remédiation avec le scoring CVSS

Failles critiques récentes

CVE-2021-44228 : Log4Shell (CRITICAL)

CVSS 10.0 - CRITIQUE

Description : Vulnérabilité d'injection de code dans la bibliothèque Apache Log4j 2 (versions < 2.15.0). Permet l'exécution de code arbitraire à distance via JNDI injection.

Découverte : Décembre 2021

Impact : Vulnérabilité critique affectant des millions de serveurs Java dans le monde. Exploitation triviale via logs contenant des payloads LDAP/RMI.

Correction : Mise à jour vers Log4j 2.15.0 ou supérieur

Leçons : Importance de maintenir à jour les dépendances, nécessité de monitoring proactif

CVE-2020-1938 : Apache Tomcat - AJP Ghostcat (HIGH)

CVSS 7.5 - ÉLEVÉ

Description : Le protocole AJP (Apache JServ Protocol) par défaut est exposé sur le port 8009, permettant la lecture de fichiers arbitraires et la révélation de code source.

Découverte : Février 2020

Impact : Exposition de données sensibles, révélation de secrets (clés d'API, tokens)

Correction : Mise à jour Tomcat 9.0.31+ ou configuration du pare-feu

CVE-2017-10271 : Oracle WebLogic Server - Deserialization RCE (CRITICAL)

CVSS 9.8 - CRITIQUE

Description : Déserialisation non sécurisée d'objets Java dans WebLogic, permettant l'exécution de code à distance sans authentification.

Découverte : Avril 2017

Impact : Exploitation active par des botnets, compromission complète des serveurs

Leçons : Éviter la désérialisation d'objets non fiables

CVE-2018-11776 : Apache Struts 2 RCE (CRITICAL)

CVSS 9.8 - CRITIQUE

Description : Vulnérabilité d'injection OGNL (Object-Graph Navigation Language) permettant l'exécution de code arbitraire.

Découverte : Août 2018

Impact : Exploitation massive de serveurs web, création de botnets

CVE-2021-3129 : Laravel Framework RCE (CRITICAL)

CVSS 9.8 - CRITIQUE

Description : Vulnérabilité dans le gestionnaire d'exceptions de Laravel permettant l'exécution de code à distance en mode debug.

Découverte : Janvier 2021

Impact : Compromission totale des applications en production avec debug=true

Leçons : Jamais activer debug en production

CVE-2021-21225 : Google Chrome V8 RCE (HIGH)

CVSS 8.8 - ÉLEVÉ

Description : Débordement de pointeur dans le moteur JavaScript V8 de Chrome.

Découverte : Mars 2021

Impact : Exploitation via pages web malveillantes, accès mémoire arbitraire

CVE-2023-34362 : Progress MOVEit Transfer - RCE (CRITICAL)

CVSS 9.8 - CRITIQUE

Description : Vulnérabilité d'injection SQL via SQLServer permettant l'exécution de code arbitraire dans MOVEit.

Découverte : Juin 2023

Impact : Exploitation massive, fuite de données sensibles chez Fortune 500

Leçons : Importance des correctifs de sécurité immédiats

📊 CVSS (Common Vulnerability Scoring System)

Définition

CVSS est un framework standardisé pour évaluer la sévérité des vulnérabilités de sécurité. Il produit un score entre 0 et 10, où 10 est le plus critique.

Objectif principal

  • Fournir une évaluation standardisée et reproductible de la sévérité
  • Permettre une priorisation cohérente des corrections
  • Faciliter la communication entre organisations sur les risques
  • Aider à l'allocation des ressources de sécurité

Versions de CVSS

CVSS v2

Métrique de base avec :

  • Access Vector (AV)
  • Access Complexity (AC)
  • Authentication (Au)
  • Confidentiality (C)
  • Integrity (I)
  • Availability (A)

Remplacée, mais encore utilisée

CVSS v3.1 (Actuelle)

Amélioration avec :

  • Attack Vector
  • Attack Complexity
  • Privileges Required
  • User Interaction
  • Scope
  • Confidentiality/Integrity/Availability

Standard actuel (2019-)

Échelle de sévérité CVSS

Score CVSS Notation Sévérité Réponse
0.0 None NONE Pas de vulnérabilité
0.1 - 3.9 Low LOW À corriger selon les calendriers réguliers
4.0 - 6.9 Medium MEDIUM À corriger dans les semaines
7.0 - 8.9 High HIGH Correction prioritaire (jours)
9.0 - 10.0 Critical CRITICAL Correction immédiate (heures)

Composantes de calcul CVSS v3.1

Score de base (Base Score)

Attack Vector (AV)

  • NETWORK - Requiert une connexion réseau (plus grave)
  • ADJACENT - Même réseau local
  • LOCAL - Accès local au système
  • PHYSICAL - Accès physique requis

Attack Complexity (AC)

  • LOW - Exploitation triviale
  • HIGH - Conditions spéciales requises

Privileges Required (PR)

  • NONE - Aucun privilège (plus grave)
  • LOW - Droits utilisateur basic
  • HIGH - Droits administrateur

User Interaction (UI)

  • NONE - Pas d'interaction requise
  • REQUIRED - L'utilisateur doit accepter/cliquer

Exemple de calcul CVSS

Log4Shell (CVE-2021-44228) - CVSS v3.1: 10.0

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H

  • AV:N - Vulnérable via le réseau
  • AC:L - Exploitation facile
  • PR:N - Aucun privilège requis
  • UI:N - Pas d'interaction utilisateur
  • S:U - Scope inchangé
  • C:H - Confidentialité complètement compromise
  • I:H - Intégrité complètement compromise
  • A:H - Disponibilité complètement compromise

Résultat : 10.0 (CRITIQUE) - Exploitation immédiate sur millions de serveurs

Calculateur CVSS

🔧 SAST (Static Application Security Testing)

Définition

SAST est une technique d'analyse automatisée du code source ou compilé pour identifier les vulnérabilités de sécurité. Les outils SAST analysent le code sans l'exécuter pour détecter les patterns dangereux.

Objectif principal

  • Identifier les vulnérabilités au plus tôt (lors du développement)
  • Détecter les patterns dangereux de codage
  • Mapper les problèmes aux CWE et OWASP Top 10
  • Intégrer la sécurité dans le CI/CD
  • Réduire le coût de correction (plus tôt = moins cher)

Types de vulnérabilités détectées par SAST

🔴 Injection d'entrée

  • SQL Injection
  • XSS (Cross-Site Scripting)
  • Command Injection
  • LDAP Injection
  • Path Traversal

🔴 Gestion d'authentification

  • Mots de passe en clair
  • Secrets commitées
  • Algorithmes faibles
  • Stockage non sécurisé

🔴 Gestion de contrôle d'accès

  • Vérifications manquantes
  • Escalade de privilèges
  • Accès non restreint aux ressources

🔴 Qualité du code

  • Null pointer dereferences
  • Buffer overflows
  • Use-after-free
  • Race conditions

Avantages du SAST

  • Détection rapide et précoce
  • Analyse complète du code source
  • Peu ou pas de faux négatifs
  • Intégration facile en CI/CD
  • Pas d'accès à l'infrastructure requise
  • Scalable à de grands projets
  • Très rentable (coût par bug bas)

Inconvénients du SAST

  • Faux positifs élevés (nécessite triage)
  • Ne détecte pas les problèmes de configuration
  • Ne teste pas les dépendances (voir DAST/SCA)
  • Courbe d'apprentissage
  • Temps d'analyse peut être long

Exemples d'avertissements Rider

❌ SQL Injection - Avertissement Rider

// Rider affiche : "Possible SQL injection"
string userId = GetUserId();
string query = $"SELECT * FROM Users WHERE Id = {userId}";
// Quick Fix : "Use parameterized query"

✅ Correction suggérée

using (SqlCommand cmd = new SqlCommand("SELECT * FROM Users WHERE Id = @id", connection))
{
    cmd.Parameters.AddWithValue("@id", userId);
    SqlDataReader reader = cmd.ExecuteReader();
}

❌ Weak Hashing - Avertissement Rider

// Rider affiche : "Use of weak cryptographic algorithm MD5"
using (MD5 md5 = MD5.Create())
{
    byte[] hash = md5.ComputeHash(Encoding.UTF8.GetBytes(password));
}
// Quick Fix : "Replace with SHA256"

✅ Correction suggérée

using (SHA256 sha256 = SHA256.Create())
{
    byte[] hash = sha256.ComputeHash(Encoding.UTF8.GetBytes(password));
}

// Meilleure approche avec salt
using (var deriveBytes = new Rfc2898DeriveBytes(password, 16))
{
    byte[] salt = deriveBytes.Salt;
    byte[] key = deriveBytes.GetBytes(32);
}

❌ Hardcoded Secret - Avertissement Rider

// Rider affiche : "Possible hardcoded secret"
private const string ApiKey = "sk-1234567890abcdef";
var client = new HttpClient();
client.DefaultRequestHeaders.Add("Authorization", $"Bearer {ApiKey}");

✅ Correction suggérée

// Configuration depuis les secrets ou variables d'environnement
var apiKey = Environment.GetEnvironmentVariable("API_KEY");
// OU utiliser User Secrets en développement
var config = new ConfigurationBuilder()
    .AddUserSecrets()
    .Build();
string apiKey = config["ApiKey"];
