✔️ Validation Model Attributes

Cheatsheet - Attributs C# et leur impact sur le HTML généré

🔴 Attributs Requis

[Required] Le champ est obligatoire

Force la saisie d'une valeur. Valide côté serveur ET client.

📝 Code C#

[Required(ErrorMessage = "Le nom est obligatoire")]
public string Name { get; set; }

🌐 HTML Généré

<input type="text"
    name="Name"
    data-val="true"
    data-val-required="Le nom est obligatoire"
    required />
💥 Impact HTML: Ajoute les attributs required, data-val et data-val-required. Le navigateur affiche une validation native.

[RequiredIfTrue] Conditionnel (Custom)

Le champ est requis si une autre propriété booléenne est vraie.

📝 Code C#

[RequiredIf("HasMiddleName", true)]
public string MiddleName { get; set; }

🌐 HTML Généré

<input type="text"
    name="MiddleName"
    data-val="true"
    data-val-requiredif="..." />
💥 Impact HTML: Ajoute data-val-requiredif pour validation JavaScript côté client avec dépendance conditionnelle.

📏 Attributs de Longueur

[StringLength] Longueur de chaîne

Valide que la chaîne a une longueur entre min et max.

📝 Code C#

[StringLength(50, MinimumLength = 3,
    ErrorMessage = "3 à 50 caractères")]
public string Name { get; set; }

🌐 HTML Généré

<input type="text"
    name="Name"
    maxlength="50"
    data-val="true"
    data-val-length="3 à 50 caractères"
    data-val-length-max="50"
    data-val-length-min="3" />
💥 Impact HTML: Ajoute maxlength, data-val-length, data-val-length-min et data-val-length-max.

[MinLength] Longueur minimum

📊 Attributs d'Intervalle

[Range] Intervalle de nombres

Valide qu'un nombre est entre une valeur min et max.

📝 Code C#

[Range(0, 150, ErrorMessage = "Âge entre 0 et 150")]
public int Age { get; set; }

🌐 HTML Généré

<input type="number"
    name="Age"
    min="0"
    max="150"
    data-val="true"
    data-val-range="Âge entre 0 et 150"
    data-val-range-min="0"
    data-val-range-max="150" />
💥 Impact HTML: Ajoute min, max, data-val-range, data-val-range-min et data-val-range-max.

[Compare] Comparaison avec autre propriété

Valide qu'une propriété est égale à une autre (ex: confirmations).

📝 Code C#

[Compare("Password",
    ErrorMessage = "Les mots de passe ne correspondent pas")]
public string ConfirmPassword { get; set; }

🌐 HTML Généré

<input type="password"
    name="ConfirmPassword"
    data-val="true"
    data-val-equalto="Les mots de passe ne correspondent pas"
    data-val-equalto-other="*.Password" />
💥 Impact HTML: Ajoute data-val-equalto et data-val-equalto-other pour validation de correspondance.

🎨 Attributs d'Affichage

[Display] Personnaliser l'affichage

Contrôle le nom affiché, l'ordre, le groupe et le format.

📝 Code C#

[Display(Name = "Adresse Email",
    Order = 1,
    GroupName = "Contact")]
public string Email { get; set; }

🌐 HTML Généré

<label for="Email">
  Adresse Email
</label>
<input type="email"
    name="Email"
    id="Email" />
💥 Impact HTML: Affecte les labels générés par @Html.LabelFor() et @Html.DisplayNameFor().

[DisplayFormat] Format d'affichage

Spécifie le format d'affichage pour les dates, nombres, etc.

📝 Code C#

[DisplayFormat(DataFormatString = "{0:dd/MM/yyyy}",
    ApplyFormatInEditMode = true)]
public DateTime BirthDate { get; set; }

🌐 HTML Généré

<input type="text"
    name="BirthDate"
    value="25/12/1990" />

<!-- ou -->
<input type="date"
    value="1990-12-25" />
💥 Impact HTML: Affecte le format de la valeur affichée dans le champ et son attribut value.

[UIHint] Indice de rendu

Suggère un modèle d'affichage personnalisé.

📝 Code C#

[UIHint("MultilineText")]
public string Description { get; set; }

🌐 HTML Généré

<textarea name="Description" rows="4"></textarea>

<!-- Utilise le template ~/Views/Shared/EditorTemplates/MultilineText.cshtml -->
💥 Impact HTML: Détermine quel template editor est utilisé pour rendre le champ.

[DataType] Type de données

Spécifie le type de données pour influencer le rendu HTML.

📝 Code C#

[DataType(DataType.Password)]
public string Password { get; set; }

[DataType(DataType.Date)]
public DateTime BirthDate { get; set; }

🌐 HTML Généré

<input type="password"
    name="Password" />

<input type="date"
    name="BirthDate" />
💥 Impact HTML: Ajoute l'attribut type approprié au champ (password, date, email, etc.).

🔧 Attributs Avancés

[Remote] Validation serveur asynchrone

Valide côté serveur en appelant une action via AJAX.

📝 Code C#

[Remote("CheckUsername",
    "Account",
    ErrorMessage = "Utilisateur existe")]
public string Username { get; set; }

🌐 HTML Généré

<input type="text"
    name="Username"
    data-val="true"
    data-val-remote="Utilisateur existe"
    data-val-remote-url="/Account/CheckUsername" />
💥 Impact HTML: Ajoute data-val-remote et data-val-remote-url pour validation AJAX asynchrone.

[Scaffold] Masquer un champ

Spécifie si une propriété doit être affichée dans les formulaires.

📝 Code C#

[Scaffold(false)]
public int Id { get; set; }

[Scaffold(false)]
public DateTime CreatedDate { get; set; }

🌐 HTML Généré

<!-- Le champ n'est pas rendu -->
<!-- Utiliser un @Html.HiddenFor() manuel si nécessaire -->

@if (Model.Id > 0) {
    @Html.HiddenFor(m => m.Id)
}
💥 Impact HTML: Empêche le rendu automatique du champ. Utile pour les IDs générés automatiquement.

[Editable] Permet la modification

Indique si le champ peut être modifié.

📝 Code C#

[Editable(false)]
public DateTime CreatedDate { get; set; }

[Editable(true)]
public string Name { get; set; }

🌐 HTML Généré

<!-- Non éditable: rendu en display -->
<span>@Model.CreatedDate</span>

<!-- Éditable: rendu en input -->
<input type="text"
    name="Name" />
💥 Impact HTML: Affecte le rendu par les templates d'édition (editor vs display).

🎯 Exemple Complet Pratique

📝 Code C# Complet

public class RegisterModel
{
    [Required(ErrorMessage = "Le nom est obligatoire")]
    [StringLength(100, MinimumLength = 3)]
    [Display(Name = "Nom complet")]
    public string FullName { get; set; }

    [Required]
    [EmailAddress]
    [Display(Name = "Adresse email")]
    public string Email { get; set; }

    [Required]
    [DataType(DataType.Password)]
    [StringLength(100, MinimumLength = 8)]
    [Display(Name = "Mot de passe")]
    public string Password { get; set; }

    [Required]
    [DataType(DataType.Password)]
    [Compare("Password")]
    [Display(Name = "Confirmer le mot de passe")]
    public string ConfirmPassword { get; set; }

    [Range(18, 120, ErrorMessage = "Âge entre 18 et 120")]
    [Display(Name = "Âge")]
    public int Age { get; set; }
}

🌐 HTML Généré (Automatiquement!)

<form method="post">

  <div>
    <label for="FullName">Nom complet</label>
    <input type="text" name="FullName"
        maxlength="100" required
        data-val="true"
        data-val-required="Le nom est obligatoire"
        data-val-length="..."
        data-val-length-min="3"
        data-val-length-max="100" />
  </div>

  <div>
    <label for="Email">Adresse email</label>
    <input type="email" name="Email" required
        data-val="true"
        data-val-email="..." />
  </div>

  <div>
    <label for="Age">Âge</label>
    <input type="number" name="Age"
        min="18" max="120"
        data-val="true"
        data-val-range="Âge entre 18 et 120"
        data-val-range-min="18"
        data-val-range-max="120" />
  </div>

</form>

💡 Conseils et Bonnes Pratiques

✅ Toujours valider côté serveur

Les attributs de validation HTML5/JavaScript côté client peuvent être contournés. Valider toujours au serveur avec ModelState.IsValid.

✅ Utiliser [Display] pour les labels

Cela rend les labels maintenables et multilingues. Ne pas écrire les labels en dur en HTML.

✅ Laisser générer le HTML

Utiliser @Html.TextBoxFor() ou asp-for plutôt que d'écrire <input> manuellement. Les helpers génèrent tous les data-val-*.

❌ Ne pas mélanger les approches

Ne pas mettre la validation HTML5 en dur (required) ET les attributs C#. Laisse les attributs C# générer l'HTML.

✅ Inclure jQuery Validation

Pour la validation côté client avec les data-val-*, inclure jquery.validate.js et jquery.validate.unobtrusive.js.

✅ Utiliser [Remote] avec modération

La validation [Remote] effectue une requête AJAX à chaque frappe. Utiliser avec délai (debounce) pour éviter le spam de requêtes.
