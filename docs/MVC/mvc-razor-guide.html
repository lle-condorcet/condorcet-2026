🎯 MVC Razor en C#

Comprendre l'architecture et les bonnes pratiques

📋 Model

  • Responsabilité Représente les données et la logique métier de l'application
  • Contenu Classes POCO (Plain Old CLR Objects) avec propriétés publiques
  • Localisation Dossier Models/ à la racine
  • Exemple User.cs, Product.cs, Order.cs

🕹️ View

  • Responsabilité Affichage des données à l'utilisateur (interface)
  • Contenu Fichiers .cshtml (HTML + C#)
  • Localisation Views/[ControllerName]/
  • Exemple Index.cshtml, Create.cshtml, Edit.cshtml

⚙️ Controller

  • Responsabilité Gère les requêtes et coordonne Model et View
  • Contenu Hérite de Controller, contient des Actions
  • Localisation Dossier Controllers/
  • Exemple UsersController.cs, ProductsController.cs

💡 Model vs View vs Controller

Model

Définit la structure des données

public class User { public int Id { get; set; } public string Name { get; set; } public string Email { get; set; } }

View

Affiche les données au client

@model User <h1>@Model.Name</h1> <p>@Model.Email</p> <a href="@Url.Action( "Edit", new { id = Model.Id })"> Modifier </a>

Controller

Traite les requêtes

public IActionResult Edit(int id) { var user = _db.Users .FirstOrDefault(u => u.Id == id); return View(user); }

Routing

Mappe les URLs aux actions

// Convention: /Users/Edit/5 // Attribut: [Route("api/users/{id}")] public IActionResult Get(int id)

⭐ Bonnes Pratiques Essentielles

  • Séparation des responsabilités - Chaque composant a un rôle unique et clair
  • Dépendance Injection - Utiliser l'injection de dépendances plutôt que new
  • Validation - Valider les données dans le Model avec des attributs [Required], [StringLength], etc.
  • Nommage cohérent - Controller = NomController, Vue = dossier du contrôleur, Models = racine Models/
  • Data Annotations - Utiliser [Display], [DataType], [RegularExpression] pour la validation côté client et serveur
  • Layouts partagés - _Layout.cshtml pour éviter la duplication de HTML
  • Asynchrone - Utiliser async/await pour les opérations longues (BD, API)
  • Logging - Logger les erreurs et événements importants avec ILogger
