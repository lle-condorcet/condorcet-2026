📄 Razor Pages en C#

Architecture simplifiée pour applications web ASP.NET Core

📋 Structure

  • Concept Une seule page = un fichier .cshtml + un PageModel
  • Fusion Combine la logique (C#) et la vue (HTML) au même endroit
  • Localisation Dossier Pages/ à la racine
  • Convention Index.cshtml + Index.cshtml.cs

⚙️ PageModel

  • Rôle Classe C# derrière chaque page Razor
  • Héritage Hérite de PageModel
  • Contenu Propriétés publiques, méthodes pour traiter les requêtes
  • Méthodes OnGet, OnPost, OnDelete, etc.

🎨 Vue Razor

  • Fichier Extension .cshtml (C# + HTML)
  • Accès au Model Via @Model ou @page
  • Binding automatique Les propriétés du PageModel sont accessibles directement
  • Directives @page, @model, @using, @inject

📁 Arborescence Standard

📦 ProjetRazorPages/ 📁 Pages/ ├─ Index.cshtml ├─ Index.cshtml.cs ├─ Privacy.cshtml ├─ Privacy.cshtml.cs │ ├─ Users/ (dossier) │ ├─ Index.cshtml │ ├─ Index.cshtml.cs │ ├─ Create.cshtml │ ├─ Create.cshtml.cs │ ├─ Edit.cshtml │ └─ Edit.cshtml.cs │ └─ Shared/ ├─ _Layout.cshtml └─ _ValidationScriptsPartial.cshtml 📁 Models/ ├─ User.cs └─ Product.cs 📁 wwwroot/ ├─ css/ ├─ js/ └─ images/ 📄 appsettings.json 📄 Program.cs
⚡ Différence clé: Contrairement au MVC, il n'y a pas de dossier Controllers séparé. La logique se trouve directement avec la page dans le fichier .cshtml.cs

💡 Anatomie d'une Razor Page

PageModel (Index.cshtml.cs)

using Microsoft.AspNetCore.Mvc.RazorPages;
using YourApp.Models;

namespace YourApp.Pages
{
    public class IndexModel : PageModel
    {
        private readonly ILogger<IndexModel> _logger;
        
        public List<User> Users { get; set; }
        public string SearchTerm { get; set; }

        public IndexModel(ILogger<IndexModel> logger)
        {
            _logger = logger;
        }

        public void OnGet()
        {
            Users = new List<User>
            {
                new User { Id = 1, Name = "Alice" },
                new User { Id = 2, Name = "Bob" }
            };
        }

        public IActionResult OnPost()
        {
            // Traiter la soumission du formulaire
            if (!ModelState.IsValid)
                return Page();

            return RedirectToPage("Success");
        }
    }
}

Vue Razor (Index.cshtml)

@page
@model IndexModel

<div class="container">
    <h1>Liste des Utilisateurs</h1>

    <form method="post">
        <input type="text"
               asp-for="@Model.SearchTerm"
               placeholder="Rechercher..." />
        <button type="submit">Rechercher</button>
    </form>

    <table>
        <tr>
            <th>ID</th>
            <th>Nom</th>
        </tr>
        @foreach (var user in Model.Users)
        {
            <tr>
                <td>@user.Id</td>
                <td>@user.Name</td>
            </tr>
        }
    </table>
</div>

🔀 MVC vs Razor Pages

🏛️ MVC

  • 3 couches séparées (Model, View, Controller)
  • Idéal pour projets complexes et grands
  • Meilleure séparation des responsabilités
  • Controller regroupe plusieurs actions
  • Logique métier dans Controllers
  • Plus de fichiers à gérer
  • Courbe d'apprentissage plus élevée

📄 Razor Pages

  • Une page = une seule responsabilité
  • Idéal pour sites simples à moyens
  • Moins de boilerplate
  • Une page = un PageModel
  • Logique proche de la vue
  • Moins de fichiers, plus lisible
  • Courbe d'apprentissage plus douce

📌 Directives Razor Pages Essentielles

@page

// Rend le fichier .cshtml
// une Razor Page routable
@page

// Options:
@page "/users/list"
@page "{id}"

@model

// Spécifie le PageModel
@model IndexModel

// Accès aux propriétés:
<h1>@Model.Title</h1>

asp-for

// Lie les éléments HTML
// aux propriétés du PageModel
<input asp-for="@Model.Email" />
<label asp-for="@Model.Name">
    Nom
</label>

@inject

// Injection de dépendance
// directement dans la page
@inject ILogger<IndexModel> logger

@{
    logger.LogInformation("Page chargée");
}

⭐ Bonnes Pratiques Essentielles

  • Une page = Une responsabilité - Chaque Razor Page doit avoir un seul but clair
  • Nommage cohérent - Index.cshtml + Index.cshtml.cs, Create.cshtml + Create.cshtml.cs
  • Validation des données - Utiliser [Required], [StringLength], [EmailAddress] dans le PageModel
  • ModelState.IsValid - Toujours vérifier avant de traiter les données POST
  • Injection de dépendances - Utiliser le constructeur du PageModel, pas new
  • Async/Await - OnGetAsync(), OnPostAsync() pour les opérations asynchrones
  • Partials réutilisables - Créer des fichiers _PartialName.cshtml pour les éléments répétitifs
  • Routing - @page "route personnalisée" si besoin, sinon la convention par défaut
  • Sécurité CSRF - ASP.NET gère automatiquement, mais vérifier les formulaires
